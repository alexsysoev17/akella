# Motion Platform — Import, Validation & AI Motion Director

По умолчанию AKELLA использует **agent-native runtime**: агент читает нужные данные, вызывает типизированные инструменты, наблюдает результат, исправляет ошибку в одной рабочей ревизии и сохраняет изменения атомарно после обязательной технической проверки. Однозначные поддерживаемые правки выполняются тем же путём без модели. Новые движения можно создавать ключевыми кадрами и безопасными математическими программами без регистрации художественного приёма. Enter запускает выполнение и Preview; Undo/Redo сохранены. При существенной неоднозначности возможен вопрос. Точная архитектура и ограничения: [architecture-handoff](docs/architecture-handoff.md#agent-native-execution--2026-11-01-partial-migration-audit).

Единое локальное приложение `apps/scene-validator` обслуживает все папки `projects/`. ZIP из Figma загружается через браузер: платформа проверяет экспорт, создаёт проект и восстанавливает сцены из **scene.json + assets**. Превью Figma — отдельные эталоны, не источник реконструкции.

Одинаковые имена слоёв теперь связывают состояния между сценами: **точное имя → logical object → переход по исходной геометрии**. Инструкция, ограничения композиции и результаты приёмки: [Object States](docs/object-states.md).

MP4 Export проверяет готовый файл декодированием: разрешение, FPS, длительность и количество кадров. В Inspector → «Экспорт» сохраняются этап, причина ошибки и диагностика, включая неудачные попытки. Слабая сохранённая инерция даёт предупреждение; настоящие дефекты движения и композиции продолжают блокировать экспорт. Full не зависит от качества вьюпорта; Draft использует выбранное уменьшенное разрешение.

В боковой панели выбранного объекта есть **Transform / Anchor**: девять точек, Center/Reset, произвольные координаты и перетаскиваемая точка во viewport. Для новых motion-документов центр используется по умолчанию; существующие сохраняют прежнее поведение. Preserve Visual Position сохраняет позу на текущем кадре постоянной компенсацией во всей выбранной области — дальнейшая траектория может измениться. Position в панели — дополнительное смещение, Scale — множитель поверх анимации.

## Direct Agent и продолжение после остановки

Все обычные запросы, включая длинные описания ролика, исполняет один Direct Agent через реальные motion tools. Обязательного Director, глобального плана и пула workers нет. При пустой настройке модели Codex явно получает `gpt-6.1-sol`; выбранная вами другая модель сохраняется.

После применённых изменений сохраняется внутренний checkpoint: `motion/direct-runs/<runId>/checkpoint.json` внутри проекта. При таймауте допускается одна автоматическая попытка продолжения с компактным контекстом. Если она не удалась, появляется «Продолжить»: восстановится тот же кандидат, а не новый запрос с нуля. Отмена не вызывает повтор. Настройки: `directTimeoutRetries`, `directContinuationBudgetMs`, `providerTimeoutMs` в `motion/harness/config.json`.

Промежуточная работа не равна готовой анимации: до окончательного сохранения viewport показывает опубликованный результат. Итог сохраняется одной транзакцией с Undo/Redo. Inspector различает вызовы модели, сохранённые batches и публичный commit. При конфликте с вашими новыми правками продолжение останавливается безопасно.

Экспериментальная Multi-Agent Production отключена от обычного пути. Её файлы и незавершённые записи сохранены, полезные исправления текста и переходов остаются в движке. Подробности — в [архитектуре](docs/architecture-handoff.md).

## Agent-First: режим проверок

По умолчанию `AGENT_VALIDATION_MODE=minimal`: агент может сразу изменять и сохранять анимацию. Художественные QA и заданные моделью проверки доступны для наблюдения, но не блокируют технически корректную транзакцию. Связанные изменения вычисляются движком и отражаются в Inspector. Сохранение не является доказательством полного выполнения художественного запроса.

`AGENT_VALIDATION_MODE=strict` включает обязательные проверки результата, declared scope и focused QA. Режим задаётся при запуске сервера. Лимита «три шага агента» и общего срока всей задачи больше нет; сохранены отмена, реальные ограничения запроса к модели и остановка повторяющихся действий без прогресса. Продолжительные задачи могут расходовать больше вызовов — их нужно отменять, если продолжение не требуется.

## Автоматическое восстановление

Новый основной runtime возвращает ошибки аргументов, математики и QA тому же агенту. Исправляются конкретные tool calls, технически проверяется кандидат, затем выполняется один commit; дополнительные QA в minimal необязательны. Полный Semantic Plan и Code Repair в этом цикле не запускаются. Structured output и технические инварианты остаются строгими; схемы примитивов и знания загружаются выборочно.

Прежние Planning/Preflight/Recovery сохранены для явно выбранного `AKELLA_MOTION_RUNTIME=legacy`, manual-response и ранее сохранённых legacy jobs. Это временная миграционная граница, не скрытый fallback новых команд. Полный паритет ещё не доказан. Исторические reference-тесты явно проверяют legacy; новые agent-тесты вызывают основной путь, включая HTTP API.

Команда «убери всю анимацию объекта, пусть он статично стоит с начала весь ролик» использует отдельную типизированную фиксацию logical object. Удаляются его эффекты во всех сценах, а native renderer показывает один исходный объект весь ролик. Это глобальное представление поверх сцен; сложные маски/клиппинг родителя явно диагностируются, browser-compat его не поддерживает. Исходный Figma JSON не меняется, Undo работает. Новая анимация освобождает эту фиксацию.

При правке существующих эффектов сохраняются их ID и базовые движения. «Чуть позже» означает небольшой сдвиг относительно **начала** anchor, «когда закончится» — относительно **конца**; связи пересчитываются вместе с инерцией. Отдельно поддерживается совмещение концов анимаций. Сила, частота и затухание — разные параметры.

Ремонт исходного кода — отдельный инженерный контур; legacy-настройки сохранены, но новый обычный motion loop его не вызывает. Он может подготовить предложение в изолированной копии и проверить его под ограничениями macOS. Рабочий код автоматически не заменяется. На других ОС запуск сгенерированных тестов блокируется до появления безопасного runner.

Для подготовленного предложения:

```sh
npm run recovery -- review --workspace "/путь/к/изолированной-копии"
npm run recovery -- export --workspace "/путь/к/изолированной-копии" --output "/путь/к/repair.patch"
```

Перед применением требуется отдельное человеческое ревью точного патча и исходной Git-ревизии. В Inspector есть «Просмотреть и применить исправление»: точный diff, одноразовое подтверждение, чистый Git на исходной ревизии, повтор исходного сценария в копии проекта. Только после успеха создаётся локальный commit. Затем проверенный результат исходного задания публикуется через обычную транзакцию с проверкой ревизии; если вы успели изменить проект, публикация блокируется и ваши правки сохраняются. Для загрузки нового кода нужен перезапуск сервера. Если полного ответа модели не сохранилось, повторное планирование у внешнего провайдера требует явного согласия в диалоге (CLI: `--allow-live-replay`). CLI: `npm run recovery -- apply --workspace PATH --approve-patch SHA256 --project PATH --run UUID`. Автоматического самоприменения нет. Дополнительная проверка живого Recovery на искусственных данных: `npm run eval:recovery -- --live` — это подготовленная ошибка планирования и настоящий вызов восстановления, а не live-тест всего понимания языка. Подробности, ограничения и результаты: [архитектура](docs/architecture-handoff.md#bounded-project-recovery-and-isolated-code-proposals--2026-10-21-v1028).

`npm run eval:recovery -- --live --typed` проверяет настоящий сериализованный tool-decision при конфликте зависимого удаления. `npm run eval:code-repair -- --live` — отдельный **платный/внешний** тест coding provider: отправляет два разрешённых файла исходников из искусственно повреждённой изолированной копии, проверяет новый тест до и после патча. Клиентские проекты не передаются. Эти команды не запускаются после обычных промптов. Level 2 управляется recovery.codeRepair.enabled (по умолчанию true), не применяет код автоматически и показывает причину, diff, тесты и риски в Inspector. На macOS тесты выполняются в OS sandbox; на других ОС runner пока блокируется.

Неуспешные запуски проходят через общий Recovery Supervisor: диагностика → применимый детерминированный/проектный ремонт → изолированное исследование исходников при необходимости. Лимиты конечные; отсутствие доступа, неоднозначный объект или исчерпанный бюджет показываются с причиной. Inspector отображает общий журнал восстановления; проверенный патч требует вашего одобрения. Это накопление проверенного опыта, а не обучение весов модели.

Если срок запуска истёк после формирования полного плана, Recovery сохраняет продолжение и выполняет его через локальный сервер с новым ограниченным бюджетом. После перезапуска очередь восстанавливается; изменение проекта блокирует устаревшее продолжение. CLI: `npm run recovery -- resume --project PATH`. Code Repair может запрашивать дополнительные исходники, callers и tests в изолированной копии; по умолчанию до 3 вызовов исследования и 12 запросов чтения. Рабочий код требует прежнего одобрения.

## Быстрые правки существующего движения

Команды вроде «пусть текст 2 появляется на 5 кадров позже», «сделай колебания лого гораздо слабее», «уменьши частоту и амплитуду», «появление телефона в два раза медленнее» выполняются локально, если объекты и текущие движения однозначны. Entrance сдвигается без exit, stagger и easing сохраняются; привязанные эффекты следуют за источником. В «Производительности» видны route/executionMode, IDs, old/new и фактическое время.

Незнакомая формулировка существующей анимации получает компактный typed patch; при необходимости разрешён один read-only раунд дополнительных данных только по целевым объектам. Новая композиция использует прежний полный planner. Все пути проходят preflight/QA/revision-safe commit и сохраняют Undo/Redo.

Контекст проверяется по профилю конкретной модели и полному запросу (system/schema/tools/output/reasoning reserve). Адаптер может предоставить contextProfile; modelProfiles в конфигурации задают точные ограничения локальных/API моделей. Codex использует доступные свежие локальные model metadata. Неизвестный профиль и приблизительный подсчёт токенов явно обозначаются в Inspector; actual usage появляется только после ответа. maxContextBytes теперь отдельный transport ceiling, а не универсальный размер окна модели. Подробнее — docs/architecture-handoff.md.

## Качество Preview и черновой MP4

В панели над видео выберите **Auto / Full / Half / Third / Quarter**. Это качество предпросмотра, а не разрешение проекта. Для1920×1080 режим Quarter действительно рендерит480×270. Auto показывает быстрый черновик, использует пониженное качество при перемотке/воспроизведении и повышает его после остановки. Настройка сохраняется только в этом браузере для выбранного проекта; AI и Motion Plan не запускаются.

**Черновой MP4** использует соседний выбор Full/Half/Third/Quarter. FPS, длительность и движение сохраняются. Обычный **Экспорт MP4** всегда использует исходное разрешение, независимо от Preview. Для нечётных размеров H264 может добавить один пиксель справа/снизу; в отчёте отдельно указаны raster и encoded dimensions. Черновая техническая QA не выдаётся за Full QA.

«Производительность» показывает реальные размеры, время рендера/доставки, среднее/p95, кеш, ресурсы и первый кадр. Если CPU не успевает за FPS проекта, Preview пропускает показ кадров; экспорт сохраняет каждый кадр.

Воспроизводимый локальный benchmark (копия проекта, прогрев, кеш кадров отключён при замерах):

```sh
npm run benchmark:preview -- --project projects/test44 --frame 270 --samples 7
```

## Native Renderer (Skia)

По умолчанию сцены рисует **CPU Skia в Node Worker**, через официальный `canvaskit-wasm@0.42.0`. Браузер показывает готовые RGBA-кадры; тот же рендерер подаёт кадры в FFmpeg. Текст остаётся редактируемыми данными, Trim Paths вырезает реальные сегменты кривых. Figma previews не используются для восстановления сцены.

Нужные шрифты должны быть установлены локально; отсутствие семейства показывается предупреждением. После установки шрифтов перезапустите сервер. `AKELLA_FONT_DIRS` позволяет задать каталоги шрифтов (на macOS разделитель `:`). Совпадение с Figma пиксель в пиксель не гарантируется.

Временный старый путь можно включить явно перед запуском:

```sh
AKELLA_RENDERER=browser-compat sh scripts/platform.sh dev
```

Автоматического скрытого переключения нет. В native пока не поддержаны градиентная заливка текста, paragraph indent и tiled image fills; часть эффектов сообщает ограничения. Word/grapheme animation требует проверки лигатур и связанных письменностей. Новый сложный кадр на CPU может считаться дольше33мс; Preview пропускает показ кадров под нагрузкой, экспорт считает каждый.

Проверки: `npm run test:native` — native pixels/API/Chromium+WebKit transport/FFmpeg; `npm run test:compat` — прежний renderer; `npm test` — оба набора. `npm run benchmark` — подготовленные reference-ответы, не live AI. Полная схема, API, лимиты и фактически измеренные результаты — в [architecture-handoff](docs/architecture-handoff.md#native-skia-rendering-migration--2026-10-19-v1019).

## Работа в браузере

1. **+ НОВЫЙ ПРОЕКТ** → название → ZIP Figma → **ПРОВЕРИТЬ ZIP** → **СОЗДАТЬ ПРОЕКТ**. Самостоятельно распаковывать архив не нужно. Поддерживаются scene.json в корне ZIP и внутри дополнительной папки.
2. Проект сразу открывает **Motion / Анимация**, без вкладок. Слева находятся все сцены и объекты; выбор сцены перемещает preview к её началу. Изображение строится из scene.json + assets.
3. Введите движение и нажмите Enter. Агент автоматически сохраняет корректные операции и запускает preview. Для контроля результата есть Undo/Redo, playhead и история. Ручных форм эффектов, блоков и переходов нет.
4. **Экспорт MP4** создаёт отдельный видеофайл.
5. **ОБНОВИТЬ ИЗ FIGMA** принимает новый ZIP и сохраняет прежний импорт в истории. Пользовательские notes, motion и renders сохраняются. Ссылка **MOTION PLATFORM** возвращает к списку проектов.

Проверка/сравнение сцен и редактор заметок удалены из пользовательского интерфейса. Ранее созданные файлы и история сохранены. Отдельные диагностические CLI-команды остаются совместимыми.

Ошибки экспорта показываются предупреждениями: целостность файлов не доказывает визуальную точность. При отсутствии preview реконструкция возможна, но сравнение явно недоступно. Ссылки на отсутствующие файлы запрещены.

## Установка и CLI

Требуется Node.js 20.19+ с npm:

```sh
npm ci
node node_modules/playwright/cli.js install chromium webkit # только для browser QA/compatibility tests
npm run check
npm run dev
npm run projects
npm run import -- --name "Red Collar Promo" --source "/path/export.zip"
npm run validate -- --project ./projects/red-collar-promo
npm run validate -- --project PROJECT_UUID
npm run create-project -- --name "Red Collar Promo" --source "/path/new-export.zip" --update
```

`create-project` и `import` используют один импортёр с веб-интерфейсом. Папка экспорта также поддерживается CLI. `validate --structural-only` проверяет только структуру. Без npm на этом Mac доступны эквиваленты `sh scripts/platform.sh projects`, `import ...`, `validate ...`. После `npm run build`: `node apps/scene-validator/dist/src/cli.js dev`. Сборка копирует локальные HTML/CSS/JS; CDN не используется. Импорт, реконструкция и MP4 выполняются локально; AI-планирование отправляет компактный контекст в Codex через существующую авторизацию ChatGPT.

## Difference maps и статусы

Сравниваются независимые PNG одинакового размера, RGBA приводится к белому фону. Метрики: число/процент пикселей с максимальной разницей RGB больше 8/255 и MAE по RGB в диапазоне 0–255. Карта показывает интенсивность различий пурпурным на чёрном; совпадение — чёрный. `identical` означает отсутствие различий выше порога, `differences` — наличие различий. Это не perceptual score и не автоматическая оценка качества дизайна. `passed` для структуры/обработки не означает совпадения с Figma.

Размер сцены ограничен 16384px по стороне, сравнение — 32 мегапикселями. Нет фиксированного лимита на число сцен. Обработка последовательная; большие проекты требуют времени и памяти.

## Как собирается изображение

1. project.json определяет относительный путь к scene.json.
2. Читаются сцены, дерево узлов, paints, текст, размеры, sceneTransform и asset references.
3. Создаётся SVG-композиция с вложенными группами. Матрица ребёнка вычисляется как inverse(parent.sceneTransform) × child.sceneTransform; это также корректно обрабатывает Group nodes, у которых exported relativeTransform может отличаться от ожидаемых локальных координат.
4. FRAME backgrounds, RECTANGLE/ELLIPSE/LINE, доступные vectorPaths/fillGeometry/strokeGeometry, gradients, image paints и sibling masks собираются из структурированных свойств. Visible/opacity, clipping, порядок слоёв, основные blend modes и drop shadows применяются в композиции.
5. TEXT остаётся браузерным текстом в foreignObject: UTF-16 styled segments, шрифт/вес/размер, letter spacing, line height, выравнивание, параграфы. Используются локально установленные шрифты; они не скачиваются и не копируются. При отсутствии шрифта выводится предупреждение, результат использует fallback.
6. IMAGE читается по assetId из оригинального файла. FILL/FIT и normalized CROP применяются к геометрии объекта. Невидимые fills пропускаются.
7. VECTOR со mixed paints либо форма без доступной геометрии использует свой **SVG asset**, с явным указанием fallback. Это ресурс отдельного узла, а не PNG всего Frame. Unsupported nodes могут использовать отдельный PNG fallback, если экспортёр его предоставил.
8. Chromium отрисовывает эту композицию в новый PNG, SCALE 1. Renderer не читает source/previews; asset, подменённый путём previews/, запрещён.
9. После завершения renderer исходное Figma preview копируется отдельно в validation/references для сравнения в интерфейсе.

Один self-contained HTML композиции сохраняется рядом с PNG. Images/SVG resources встроены как data URI для автономной загрузки renderer; исходные PNG bytes не перекодируются до окончательной отрисовки композиции. Это требует памяти пропорционально данным сцены. Файлы шрифтов в HTML не встраиваются.

## Импорт, история и повторные проверки

`create-project` принимает экспортную папку с scene.json, родительскую папку с motion-project/ или ZIP с одним корнем экспорта. `--projects-dir` задаёт другую коллекцию проектов. Название Red Collar Promo создаёт red-collar-promo.

Для повторного импорта:

```sh
npm run create-project -- --name "Red Collar Promo" --source "/path/to/new-export.zip" --update
```

Без --update существующий проект не перезаписывается. С --update сохраняются projectId/settings, notes/, motion/, renders/ и history. Предыдущие source/, project.json и validation/ помещаются в history/imports/<importId>/. Новый импорт проверяется в staging, inventory копии сверяется с исходником до публикации. Источник экспорта не удаляется.

При каждом validate старый validation/ целиком заменяется готовым staging-каталогом; устаревшие PNG/HTML/references исчезают. source/ не записывается. Импорт/валидация сериализованы .project-lock. Обычные ошибки переключения source откатываются; несколько rename при reimport не дают гарантию общей транзакции при отключении питания. При аварии может остаться lock/staging — сначала убедитесь, что процесс остановлен, и проверьте историю перед ручной очисткой.

## Проверки и ограничения

`npm run check`: strict TypeScript, **83 теста**, build. Тесты проверяют множество проектов, 16 сцен, reimport/history/notes, ZIP/JSON/files/reference integrity, path traversal/symlinks, stale outputs и настоящий localhost server. Тест renderer проверяет **реальные PNG pixels**: изменение preview не влияет на результат, изменение JSON геометрии/цвета влияет. Browser test проверяет загрузку PNG и переключение restoration/reference/overlay.

Структурный PASS не означает pixel-perfect результат. Отчёт отдельно указывает reconstruction status, предупреждения и fallback usage. Difference maps и RGB-метрики доступны вместе с наложением; оценку приемлемости различий выполняет пользователь.

Текущие ограничения renderer явно отмечаются предупреждениями:

- TILE approximated as FILL; image filters и paint rotation не реализованы.
- CROP требует визуальной проверки normalized transform; пока не обещается поддержка всех crop случаев.
- Text fills поддерживаются точно для SOLID; прочие text paints approximated. Figma и Chromium могут различаться по shaping/line breaks/antialiasing.
- Corner smoothing, partial ellipse arcs, shadow spread, inner shadow/blur и ряд сложных эффектов не реализованы.
- Для stroke без strokeGeometry non-center alignment approximated as CENTER. Сложные/rotated SVG fallbacks могут иметь отличающиеся export bounds.
- Сложные mixed vector paints требуют SVG fallback; это не гарантирует Trim Paths.
- PNG renderer ограничен 16384px по стороне. ZIP import — 512 MiB и 50 000 entries; это ограничения ресурсов, не числа сцен.
- Отдельная ошибка reconstruction сохраняется в отчёт; source остаётся неизменным. Fonts/browser runtime required. Отказ одной сцены сохраняется отдельно, остальные сцены продолжают обрабатываться.

Сервер обслуживает каталог/API, разрешённые previews, notes и результаты validation проектов. Произвольные source/system paths не выдаются. Motion API дополнительно обслуживает операции, планы Codex, preview и MP4. Нет визуального редактора таймлайна, аудио и семантического сопоставления объектов между сценами.

## Semantic Intent и полнота исполнения

Автоматический Motion Agent теперь сначала строит LLM-контракт всего запроса и проверяет структуру и полноту контракта детерминированно; отдельный LLM audit не вызывается в стандартном успешном пути. Сцены, наследование «аналогично», несколько техник одного объекта и временные зависимости сохраняются до генерации операций. Начала сцен переводятся в кадры реальным FPS; успешные задачи сохраняются независимо. Итог сверяется по требованиям и выводится как SUCCESS / PARTIAL_SUCCESS / FAILED.

Trim Paths QA сохраняет реальный Chromium render, проверяет centerline/dash/progress/направление и сравнивает reveal с полным объектом на том же кадре. Монотонность общего числа экранных пикселей больше не используется.

`npm test` включает EVAL_MULTI_SCENE_COMPOSITE_REQUEST. Дополнительный внешний тест: `npm run eval:semantic` (настоящий Codex, искусственные fixtures, нужна авторизация). Формат контракта независим от провайдера; готовый адаптер сейчас только Codex SDK/CLI. [Архитектура, причины сбоя и ограничения](docs/task-execution.md).

## Текстовая анимация

Нативный TEXT поддерживает блок, строки, слова и Unicode-графемы. Примеры: «Headline появляется сверху из-за кадра построчно через фейд»; «Слова Headline появляются по очереди снизу»; «Сделай появление строк Headline быстрее». Упоминайте реальный текстовый объект, если названия неоднозначны. Движок вычисляет сегменты и задержки без отдельных сохранённых объектов на каждую букву.

Разметка фиксируется после загрузки локальных шрифтов. Поддерживаются stagger, обратный порядок, локальная маска и позиционная инерция от существующего evaluator. После обновления программы перезапустите сервер и обновите страницу; новый экспорт не требуется, если уже есть нативные TEXT-данные. Растровые надписи и векторные контуры не превращаются в буквы. Независимая анимация сложных лигатур и совпадение с отсутствующим Figma-шрифтом не гарантируются. Подробности: [каноническая архитектура](docs/architecture-handoff.md#native-text-animation-integration--2026-10-15).

Техническая диагностика дрожания текста: `npm run diagnose:text -- --project projects/PROJECT --scene SCENE_ID --target NODE_ID --from 29 --to 90 --output artifacts/text-quality/CASE --all-frames --video`. Без npm: `sh scripts/platform.sh diagnose-text ...`. Команда работает с временной копией, создаёт четыре абляции, покадровые трассы, контактные листы и диагностические видео. `--crop x,y,width,height` ограничивает область; `--isolate` скрывает остальные объекты только в диагностическом кадре. Режим staggered требует положительного интервала: неуказанный/нулевой интервал получает дизайн-дефолт; явное одновременное появление задаётся simultaneous. SUCCESS означает исполнение и доступные технические проверки, а не художественное одобрение.


## Проверка моделей и обслуживание истории

Архитектура использует общий адаптер провайдера, компилятор и QA. Готовых адаптеров API/локальных моделей пока нет. После реализации и регистрации адаптера его нужно проверять на том же наборе задач:

```sh
npm run benchmark:qualify -- --provider codex-sdk --model "<реальный-ID-модели>" --output artifacts/harness/model-qualification.json
```

Команда делает реальные платные/лимитируемые вызовы и требует явный ID модели. Восемь сценариев проверяют создание, составные эффекты, последовательность, несколько сцен, редактирование, удаление, неоднозначность и текст. Это диагностический допуск для проверенных сценариев, не гарантия художественного качества и не автоматический запрет других моделей в UI. Обычные запросы эти evals не запускают.

В `motion/harness/config.json` проекта можно задать `modelProfiles`: массив объектов с `provider`, `model`, `contextWindowTokens`, `maxOutputTokens`, `transportOverheadTokens`. Значения должны соответствовать реально подключённой модели. Бюджет учитывает сообщения, схему ответа и инструменты; без токенизатора используется консервативная оценка по байтам. Превышение отклоняется до вызова, без обрезания объектов или инструкций.

Для большой истории доступно **явное** архивирование:

```sh
npm run harness -- archive-history --project "/полный/путь/к/проекту" --keep 100
```

Полная прежняя история сначала сохраняется в `motion/history-archives/`. Текущее состояние и redo сохраняются; активная глубина undo сокращается до выбранного числа. Это уменьшает рабочий JSON, но не общий объём на диске. Автоматически пользовательская история не удаляется. Не запускайте обслуживание без необходимости; архивирование не является новым импортом проекта.


## Регрессии положения текста в браузерах

`npm test` запускает основной набор последовательно, затем отдельную проверку реальных пикселей Chromium/WebKit. Для нового окружения установите тестовые браузеры: `npx playwright install chromium webkit`. Быстрый отдельный запуск: `npm run test:text-placement` (после `npm run build`).

WebKit использует SVG-перемещение текста: это устраняет потерю исходной Figma-позиции при HTML-композитинге внутри foreignObject. Chromium и MP4 сохраняют прежний compositor для плавного движения. У WebKit остаётся ограничение на движение меньше пикселя; одинаковая геометрия не означает побитово одинаковые глифы или плавность во всех браузерах.

### Глобальное время и видимое окно

Анимации и эффекты поддерживают отрицательный `startFrame` и интервалы за пределами ролика. Кадр0 показывает уже пройденную часть pre-roll; сдвиг не переносит начало видео и не увеличивает его длительность автоматически. Preview/MP4 используют окно `[0, durationFrames)`. Связанные анимации следуют за anchor один раз; отдельный сдвиг зависимого объекта меняет offset, сохраняя связь. `sceneAnchors` — необязательные организационные времена; старые проекты читаются без миграции. В native renderer координаты за viewport сохраняются, ограничиваются только выходные пиксели и реальная численная/ресурсная безопасность.

Регрессии: `signed-time.test.ts`, `native-signed-time.test.ts`; входят в `npm run check`. Проверки двух исторических запросов используют сохранённые ответы AI на изолированных копиях, а не новый live NLU-вызов. Ограничения и измерения описаны в `docs/architecture-handoff.md`.


## Длительность и FPS

«Настройки → Видео → Сохранить параметры видео» обновляет проект одной транзакцией. При увеличении длительности существующая анимация не растягивается; при сокращении поздние анимации остаются в проекте и показывается предупреждение. Повторное расширение снова включает их в воспроизведение.

Смена FPS по умолчанию сохраняет время в секундах. Явно заданная задержка «20 кадров» остаётся 20 кадрами. Старые записи без исходных единиц переводятся по документированной политике сохранения секунд; приложение сообщает об этом. Поддерживаются целые FPS 1–60; дробные FPS пока не поддерживаются. Undo/Redo возвращает всю настройку вместе с временными данными.

Проверки времени и транспорта входят в `npm run check`: `project-time.test.ts`, `provider-transport.test.ts`, `native-project-time.test.ts`. Повтор исторического ответа без внешнего вызова: `npm run benchmark:replay -- --project PATH --run RUN_ID --recorded-state`. Это тест исполнения сохранённого ответа, а не новая проверка понимания языка моделью. [Подробности архитектуры и ограничений](docs/architecture-handoff.md#provider-transport-and-canonical-project-time--2026-10-28-v118).


## Motion Skills / Библиотека анимаций

Откройте `http://127.0.0.1:4173/#skills` или ссылку «Библиотека анимаций» в настройках проекта. Каталог объединяет существующие возможности, presets и рекомендации; для Text Handoff доступна настоящая интерактивная демонстрация Skia.

Пример запроса: «Text 1 уходит влево через фейд, Text 2 появляется справа на его место без наложения». Агент может связать две обычные анимации навыком `text.handoff.no-overlap`. Проверяется видимое пересечение глифов, а не только прямоугольников. При свободном тайминге входящий текст автоматически задерживается минимально найденным безопасным способом; явные старты и конечные позиции сохраняются. «Разреши наложение» и «нужно пересечение» задают разные проверяемые политики.

Inspector → QA показывает навык, исходные интервалы, коррекцию и проверки до/после. При жёстком конфликте проект не изменяется. Сейчас автоматическое исправление использует задержку; обходные траектории ещё не реализованы. Проверка ограничена5секундами и штатным бюджетом кадров. Для существующих проектов без нового навыка поведение не меняется. Подробнее: [каноническая архитектура](docs/architecture-handoff.md).


## Сохраняемые правила движения

Можно задавать правила для существующих и будущих движений: «У телефона всегда инерция после движения», «У звёзд постоянное покачивание». Уточнение «Убери покачивание у звезды1» сохраняет объектное исключение, а «Сделай колебания звезды2 вдвое слабее» меняет амплитуду с сохранением базовой анимации и IDs. Для общего действия нужна явная область: «У всех объектов…»; отсутствие имени не разрешает менять весь проект.

Поддержаны правила инерции, wiggle, отключения fade и easing движений; project/object/scene/time scope, исключения, Undo/Redo и смена FPS. В Inspector → QA видны правила, источники и материализованные эффекты. Прямой эффект, конфликтующий с новым правилом, требует разрешения конфликта — система не удваивает его молча. Подробности и проверенные ограничения: `docs/architecture-handoff.md`, раздел Persistent Semantic Motion Editing. Для целевой проверки используйте `node --import tsx --test apps/scene-validator/tests/native-rules.test.ts` после `npm run build`.
