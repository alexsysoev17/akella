# Semantic Intent → исполнение → QA

Автоматический workflow сначала интерпретирует полный исходный текст через LLM, затем отдельно проверяет полноту плана. Операции не создаются до проверки контракта. Код находится в `apps/scene-validator/src/motion/intent/`.

## Причины сбоя в test4

Сохранённый run: `projects/test4/motion/ai/4de6a5df-abb8-42fe-80ce-d67d859a5320/`.

1. Старый разбор удалял переносы строк перед разделением инструкций. «Лого аналогично сцена3… trim paths» становилось одной задачей, и логотип получал технику следующей сцены.
2. Планировщик выделял только две специальные техники: Trim Paths и инерцию. Fade и изменение начала сцены не попадали в задачи.
3. Ограничение ремонта одной техники превращалось в запрет изменения блоков и других эффектов для всей задачи. Провайдер прямо сообщал, что начало сцены и Fade запрещены.
4. QA требовала монотонного увеличения общего числа видимых пикселей. Это неверно для пути с clipping/перекрытиями. На исторической ленте 2 воспроизводятся 63 369 → 45 337 пикселей при правильно меняющемся dash offset. Дополнительно длина outline смешивалась с длиной centerline.
5. Шесть технических задач ошибочно считались полным пользовательским намерением. Два начала сцен и восемь объектных требований должны учитываться отдельно от количества операций и задач.

## Контракт и провайдер

`schema.ts` задаёт общий формат: requirementId, исходная цитата, сцена, target, техники, параметры, timing, источник наследования, ограничения, диагностика. `coverage` связывает фрагменты исходного текста с требованиями. Сохраняются оригинальные фразы, не только пересказ.

`IntentProvider.interpret/audit` — независимый от модели интерфейс. Реализован адаптер существующего Codex SDK/CLI; OpenAI API, Claude и Local LLM пока не подключены. Они могут реализовать этот же интерфейс без изменения исполнителя. Ручной JSON-режим сохраняет прежний workflow и не предоставляет автоматической семантической интерпретации.

LLM разрешает контекст сцены, «аналогично», ссылки и временные зависимости. Независимый audit проверяет полноту, затем код проверяет schema, цитаты, покрытие текста, реальные IDs, неоднозначные цели, зависимости и наследование. Неоднозначная идентичность блокирует только соответствующее требование. Полнота смысла проверяется LLM и регрессионными evals: формальная проверка цитат сама по себе не доказывает идеальное понимание произвольной речи.

## Исполнение и scope

`compiler.ts` создаёт задачи из контракта. Slide, Fade, Trim Paths, Scale и позиционная инерция компилируются кодом. Более сложные техники используют ограниченный provider repair; неподдерживаемая операция не считается выполненной. «Аналогично» наследует параметры движения, но не геометрию чужого объекта. Изменение существующей анимации сохраняет IDs.

Все начала сцен применяются одной атомарной задачей: секунды переводятся в кадры реальным FPS. Последовательность блоков сохраняется, соседние интервалы пересчитываются; анимации и выражения сдвигаются относительно сцены, при сокращении интервала сжимаются. Конфликт порядка или недостаточный интервал дают явную ошибку. Зависимость второй ленты от конца первой хранится в `timingDependencies`; изменение длительности первой пересчитывает вторую.

User Request Scope — весь контракт; Task Scope — одно требование; Repair Scope — только исправляемые операции. Ограничение ремонта инерции не запрещает отдельную задачу начала сцены или Fade. State diff охраняет чужие объекты и техники, учитывает допустимое пересчитывание зависимостей и сравнивает массивы по стабильным IDs.

Каждая успешная задача сохраняется существующей `changeMotion` с revision/source guard и snapshot. Независимая ошибка не отменяет успех остальных. Repair feedback содержит taskId, requirementIds, targetId, ожидаемые техники, фактические операции, причину, failedChecks, capabilities и разрешённые действия. Максимум три попытки; одинаковый кандидат с одинаковой ошибкой прекращает цикл. Количество попыток не увеличено.

Финальная сверка проверяет сохранённое состояние по каждому требованию: target, техники, Fade endpoints, параметры, timing, зависимости и QA. Результат — SUCCESS / PARTIAL_SUCCESS / FAILED. UI считает требования, а не только задачи, и запускает сохранённый результат.

## Trim Paths QA

Сохраняются проверки исходной геометрии и фактический Chromium render. Reveal использует отдельную centerline mask, не scale. Проверяется progress, длина реального mask path, dash offset и направление; left/right учитывают трансформацию исходного пути.

Визуальная проверка сравнивает эффект с полностью раскрытым объектом **на том же кадре**. Число пикселей разных кадров не обязано быть монотонным. Если параметры верны, но эффект не виден в контрольных кадрах, возвращается WARNING с диагностикой offscreen/clipping/occlusion, а не выдуманный PASS видимости. Проверка выборочная, не всех кадров. Самопересечения широких лент и художественное качество не гарантируются.

## Диагностика и повторяемые проверки

`motion/ai/<runId>/`: intent-draft-N.json, intent-audit-N.json, intent-contract.json, tasks.json, execution.json, proposal.json или error.json. Сохраняются request/context и ответы провайдера. QA лежит в `motion/qa/<runId>/<taskId>-attempt-N/`.

`npm test` включает `EVAL_MULTI_SCENE_COMPOSITE_REQUEST`: 10 требований, 9 задач, шесть Slide+Fade, четыре инерции, только две ленты Trim Paths, последовательность, сохранение независимого успеха и scope regression. Отдельно проверяются 24/30/60 FPS и реальный Chromium renderer. Общий пакет содержит сравнение preview и MP4 через существующий renderer.

`npm run eval:semantic` запускает настоящий Codex на десяти **искусственных** языковых сценариях. Требуются авторизация Codex и доступ к провайдеру; это платный/лимитируемый внешний вызов. Результат: `artifacts/composite-intent/real-provider-language-evals.json`. Логи провайдера сохраняются в временном fixture-каталоге, путь печатается командой. Mock-тесты не выдаются за проверку LLM или реального Figma-документа.

Фактические результаты текущей приёмки записаны в `artifacts/composite-intent/`. Исходный test4 не изменяется во время проверки: настоящий сценарий исполняется на копии его source и motion.
