# AI Motion Director — Phase 3

## Запуск и рабочий сценарий

На текущем Mac:

```sh
cd "/Users/redcollar/Desktop/Работа/platform"
sh scripts/platform.sh dev
```

Открыть http://127.0.0.1:4173/, выбрать проект — сразу открывается **Motion / Анимация**. Сервер слушает только loopback. Если сервер уже запущен, достаточно обновить страницу. На другом компьютере нужны Node.js 20.19+, `npm ci`, `node node_modules/playwright/cli.js install chromium`, `npm run check`, `npm run dev`. Runtime анимации собирается автоматически перед dev/test; после build можно запускать `node apps/scene-validator/dist/src/cli.js dev`.

1. Выберите сцену и объект в списке слева либо щёлкните по нему в preview. Агент также может найти объект по уникальному имени/тексту из промпта.
2. Введите «Ролик 4 секунды, 30 FPS. Выбранный текст появляется снизу через 0.5 секунды за 0.6 секунды с fade и мягким easing» и нажмите **Enter** либо **Выполнить**. Shift+Enter добавляет строку.
3. Агент получает актуальный Motion State, последние запросы и принятые допущения и применённую историю. После проверки корректные операции автоматически сохраняются. Никаких Apply/Accept/Discard нет.
4. Preview перемещается к началу изменённого участка и автоматически воспроизводится. Статусы: понимаем запрос → создаём движение → сохраняем → воспроизводим. MP4 для этого не нужен.
5. Следующим промптом измените результат: «Сделай появление на полсекунды позже», «Колебания вдвое медленнее», «Амплитуду уменьши вдвое». Агент редактирует существующие анимации и сохраняет остальные параметры. История сохраняется между открытиями страницы.
6. **Отменить / Повторить** работают с атомарными snapshots. Невалидный ответ запускает до трёх попыток автоматического исправления. Если результат получить не удалось, показана техническая ошибка, motion.json не меняется. Уточняющих вопросов нет.
7. **Экспорт MP4** остаётся отдельной кнопкой. После счётчика кадров появится ссылка скачивания.

В Figma Test сохранён прежний проверенный пример; его можно редактировать новым единственным полем промпта. Автоматическое применение относится только к валидированным Motion Operations. Приложение не выполняет JavaScript от AI и не обходит разрешения Codex.

Интерфейс проекта состоит из сцен/объектов, preview и AI-поля с историей. Вкладки «Раскадровка», «Проверка», «Заметки» и кнопка проверки всех сцен удалены. Формы ручных анимаций и блоков/переходов удалены; эти операции остаются доступны агенту. Технические требования, видимость, Undo/Redo и экспорт MP4 сохранены. Выбор сцены слева перемещает playhead к началу её блока. Исходные PNG-превью не используются для изображения сцены.

Также изменены package.json/package-lock.json, scripts/build-ui.mjs, scripts/platform.sh, .gitignore, README; добавлен tests/motion.test.ts. Figma Exporter не менялся: повторная установка плагина для Phase 3 не нужна. Импорт и визуальная валидация продолжают работать через прежнюю бизнес-логику.

AI выдаёт только данные Motion Operations; исполнитель сервера применяет их автоматически. Порядок: контекст → план со строгой схемой → проверка ссылок/времени/конфликтов → автоматическая единая запись state+history. Неверная операция отклоняет всю транзакцию. Revision защищает от применения устаревшего предложения. История содержит request, origin, operations и snapshots before/after; новая правка после Undo отсекает ветку Redo.

```text
project/
├── source/                   # только чтение
├── notes/                    # пользовательские записи сохраняются
├── motion/
│   ├── motion.json           # version, revision, sourceFingerprint, state, history
│   ├── provider.json         # провайдер и модель, без паролей/токенов
│   └── ai/<request-id>/      # context, request, raw response, proposal/error/trace
└── renders/
    ├── motion-<uuid>.mp4
    └── motion-<uuid>.json    # FPS, число кадров, source/revision, предупреждения
```

Motion State не меняет исходный scene.json. Реестр точных имён обновляется при reimport; переходы логических объектов разрешают состояния из новых source refs. Старые анимации конкретных node IDs не переназначаются. Ошибки ссылок сохраняются в motion/source-reference-report.json; некорректные состояния не рендерятся до исправления. Подробнее: [Object States](object-states.md).

## Операции, эффекты и время

Поддержаны addAnimation/removeAnimation/updateAnimation, shiftAnimation, setStartFrame/setDuration/setEasing/setEffectParameters/setKeyframes, setBlockStart/setBlockDuration/setSceneTransition, setProjectDuration/setProjectSettings/setBlocks, setVisibility, stagger.

Эффекты: fadeIn/out, slideUp/Down/Left/Right, scaleIn/out, rotation, moveTo, oscillation/dampedOscillation, trimPath и keyframes. Easing: полный реестр стандартных семейств и параметрические/custom кривые — см. [Advanced Motion](advanced-motion.md). Stagger — операция над набором анимаций. Oscillation вычисляется аналитически по кадру, без накопления состояния. Сочетать fade + slide разрешено; перекрывающиеся enabled-анимации одного свойства одного объекта отклоняются.

Все startFrame глобальные относительно ролика; durationFrames задаёт интервал интерполяции. Первый исходный value удерживается до начала, конечный — после завершения. Экспортируются кадры `0..durationFrames-1`. Если требуется конечное значение на последнем видимом кадре, завершайте эффект не позднее `durationFrames-1`. Seek не зависит от предыдущих кадров.

x/y и moveTo — смещения от исходного положения Figma в осях родителя; rotation/scale выполняются вокруг исходного верхнего левого угла объекта. Opacity умножается на исходную opacity. Иерархия, clipping и трансформации renderer сохраняются. Объект родителя влияет на детей. Это определённая семантика первой версии, не полный аналог transform controls After Effects.

Блоки ссылаются на sceneId; количество определяется проектом, нет отдельных функций для трёх сцен. Cut соединяет соседние границы; Crossfade перекрывает блоки на указанное число кадров. В Crossfade следующая композиция появляется поверх предыдущей. Не допускаются gaps, неизвестные сцены, более двух одновременно активных блоков или выход за длительность. Операции за пределами проекта отвергаются; продолжительность автоматически не увеличивается.

Trim Path доступен только для простого VECTOR с одним исходным path, без fill, с одной центральной stroke, без strokeGeometry. SVG fallback, маски и переведённые в заливку обводки не объявляются совместимыми. Trim применяется через pathLength/dashoffset. Маски нельзя анимировать как обычные самостоятельные объекты. Для сложных форм нужна будущая поддержка исходных путей.

## Фактический статус Codex

Установлен официальный `@openai/codex-sdk@0.162.1`. Используются `Codex.startThread()` и `thread.run(..., { outputSchema })`. SDK запускает существующий Codex CLI, авторизованный через ChatGPT; прямого OpenAI API client/API key в приложении нет. Поле модели передаётся только если заполнено; доступность конкретного model ID определяется аккаунтом. Название Astra не зашито и его доступность не обещается.

11 октября 2026 на этом Mac проверены **настоящие запросы SDK**: создание анимации Figma Test и отдельное изменение тайминга. CLI fallback также получил настоящий структурированный ответ с уточняющим вопросом. Это не mock. Проверенная авторизация — `Logged in using ChatGPT`; успешный запрос на текущем аккаунте не гарантирует доступ на другом компьютере или после изменения лимитов.

Поиск бинарника: `MOTION_CODEX_BIN`, установленные пути Codex на macOS, затем PATH. Для другого расположения задайте `MOTION_CODEX_BIN=/absolute/path/codex` при запуске. Login проверяется через CLI; приложение не читает токены и не сохраняет их в проект. Нужен установленный и авторизованный Codex. Если SDK недоступен, пользователь явно выбирает **Codex CLI** или **Ручной обмен с Codex**. В ручном режиме копируются запрос + JSON schema; ответ вставляется обратно и проходит тот же валидатор. Поддельной успешной анимации при ошибке провайдера нет.

Запрос отправляет компактные имена, IDs, текст, размеры/позиции, выбор объекта, настройки и текущий Motion State. Не отправляет бинарные assets или весь исходный Figma JSON. Инструкции/заметки дизайна не исполняются. Shell, file editing, browser, MCP/apps/plugins и subagents отключены в planner; ответ с tool execution отклоняется. Трасса записывает типы событий и usage. AI требует сети к Codex; реконструкция и видео работают локально.

Документация интеграции: [официальный TypeScript SDK](https://learn.chatgpt.com/docs/codex-sdk), [non-interactive CLI](https://learn.chatgpt.com/docs/non-interactive-mode). Проверялись также typings реально установленного пакета.

## Ограничения

- Точность дизайна ограничена существующим renderer: шрифты, shaping, crop, сложные paints/эффекты могут отличаться от Figma. Pixel-perfect не обещается. Missing fonts требуют установки пользователем; файлы шрифтов не скачиваются.
- Нет Object Matching, AI-генерации графики, аудио, видео-таймлайна, автоадаптации анимации после обновления Figma. AI может составить неподходящий план: Некорректный план не применяется; корректный применяется автоматически, после чего доступен Undo.
- Первый UI использует JSON для параметров эффекта, keyframes и блоков. Нет drag-and-drop keyframe editor и произвольного anchor.
- MP4: H.264 без аудио, до 4096px по стороне, 60 FPS, 108000 кадров. Нечётный размер дополняется до чётного для yuv420p. FFmpeg идёт локальной зависимостью; `MOTION_FFMPEG_BIN` позволяет указать свой executable. Рендер последовательный и может быть медленным.
- Границы схемы: 1000 блоков, 5000 анимаций, 500 операций за транзакцию, контекст AI до 300000 символов; слишком большой запрос отклоняется явно. Это ресурсные ограничения, не лимит на 3 или 15 сцен.
- Pending jobs хранятся в памяти сервера; перезапуск прерывает ожидание. Успешные state/AI files/MP4 остаются на диске. История snapshots и render-файлы требуют места; автоматической очистки пользовательских результатов нет.

## Autonomous Runtime — актуальная политика

Прежние вопросы возникали из-за разрешения вопросов в plannerInstructions и допуска questions[]/needs-clarification в исполнителе. Эти ветки удалены из обычного workflow. Structured output теперь содержит status ready|unsupported, summary, assumptions, warnings, operations. Legacy questions[] поддерживается только для чтения старых архивов/ручных ответов: непустой список отклоняется программно и не показывается как вопрос.

Новый motion/autonomy.ts реализует resolveTarget и runAutonomous. Выбор: выделенный объект → совпадение имени/текста → активная сцена → предыдущий контекст → наиболее вероятный визуальный объект. Среди кандидатов выбор детерминированный; допущения сохраняются. Mask может переводиться в анимацию родительского контейнера с явным ограничением. Пользователь может исправить выбор следующим промптом или Undo.

Runtime делает максимум 3 вызова. Вопрос, неподдерживаемый easing, конфликт, неверные ссылки, пустые операции или операции без фактического изменения возвращаются модели как runtimeFeedback с конкретной причиной. Новая попытка заново проверяет полный план относительно неизменённого исходного Motion State. Изменения публикуются только одной корректной транзакцией. Auth/network/tool-boundary ошибки не обходятся. Системные разрешения Codex не отключены; доступ к OS не расширен.

В motion/ai/<request-id>/ сохраняются context.json, request.json, attempt-N.json, attempt-N/{request.txt,output-schema.json,raw-response.json,provider-trace.json}, итоговый proposal.json (внутренний журнал), execution.json или error.json. История motion.json теперь сохраняет assumptions и warnings вместе со стабильным editId; старые истории читаются с пустыми значениями. UI показывает эти записи и ограничения, без вопроса/approval stages.

Реальная приёмка автономного режима: три настоящих SDK-запроса на отдельной синтетической RED COLLAR копии. Агент самостоятельно выбрал slideUp 80px за21 кадр с overshoot, затем dampedOscillation amplitude12/cycles2/damping6. «Колебания чуть медленнее» изменила только cycles 2→1.5. «Сделай более энергично» усилила offset80→100, amplitude12→16, cycles1.5→1.8 без замены IDs и изменения проекта/других объектов. Каждый запрос auto-applied/autoplay; вопросов и confirmation buttons не было, browserErrors=[], Undo восстановил предыдущую версию, source не изменился. Это реальные AI-вызовы на синтетической копии, не новый Figma-экспорт.

Технические границы сохраняются: построчный текст без отдельных строк приближается появлением всего текстового контейнера; сложные SVG не дают автоматический Trim Paths; фундаментально новый графический эффект требует расширения engine/renderer. Такое приближение явно отмечается в warnings и истории. Если даже приближение технически невозможно, после ограниченных попыток показывается ошибка, а не ложный успех.

## Минималистичный интерфейс

Светлая двухколоночная компоновка: слева выбранный проект и узкие строки сцен, справа видео, таймлайн и промпт. Каждая строка содержит маленькую миниатюру и раскрывается по клику в дерево объектов. Миниатюры независимо собираются из scene.json и assets через renderer, а не source/previews. Двойной клик не нужен; повторный клик сворачивает сцену. Выбор сцены перемещает playhead; выбор объекта задаёт контекст агенту.

Кнопка «Настройки» снизу слева открывает окно с параметрами видео, циклическим воспроизведением, точным кадром, видимостью выбранного объекта, провайдером/моделью, историей, готовыми видео и обновлением из Figma. Escape закрывает окно. Undo/Redo и экспорт MP4 остаются над видео. Enter выполняет промпт; Shift+Enter переносит строку. Интерфейс адаптирован к узким экранам.

Таймлайн отображается неподвижными серыми палочками: вокруг текущего кадра высота меняется линейно через три промежуточных уровня. Наведение и движение курсора перематывают без нажатия; клавиши Left/Right/Home/End и touch-drag тоже поддерживаются. Светлая тема выделяет пик тёмным, тёмная — светлым. Тема меняется в настройках и сохраняется в localStorage; начальная тема тёмная (#1A1A1A/#F2F2F2, акцент #FF2B2F). UI использует локально установленные Inter Regular/Medium, letter-spacing −0.05em и уплотнённую высоту строк. Из исходного дизайна шрифты объектов не заменяются. Рамка/подложка вокруг видео и служебные подписи удалены; бренд интерфейса — SOFTWARE THAT CREATES.

## Переходы логических объектов (12 октября 2026)

Реестр exact-name, animateObjectStateTransition, дискретная смена иерархии и реальная AI/MP4-приёмка описаны в [Object States](object-states.md).
