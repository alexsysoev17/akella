# Идентичность объектов и переходы между состояниями

## Как пользоваться

1. Обновить страницу платформы: http://127.0.0.1:4173/.
2. Открыть проект с несколькими сценами. Слои с одинаковым **точным** именем получают общий logicalObjectId. Рядом со слоем отображается число состояний. В настройках выбранного объекта доступны исходный nodeId и logicalObjectId.
3. Для существующего `test3`: «Объект “куар” из второй сцены плавно увеличивается и перемещается в положение из третьей сцены. Добавь небольшой overshoot и затухающие колебания».
4. «Сделай движение быстрее, а отскок сильнее» редактирует существующий переход. Enter применяет операции и запускает autoplay; Undo/Redo и MP4 работают как раньше.

Если в проекте уже есть отдельные анимации самого слоя, его родителей или потомков, агент должен заменить конфликтующие операции в том же запросе. Независимые объекты сохраняются. Имена в запросе должны соответствовать реальным слоям: `куар` не переименовывается в `QR` автоматически.

## Данные и совместимость

`motion/object-registry.json` — производный реестр schemaVersion 1.0.0. Идентификатор — `object_` + SHA-256 точной UTF-8 строки имени. Нет trim, изменения регистра, fuzzy matching, сравнения картинок или AI matching. Scope — конкретный проект. Корневые Frame сцен исключены. Старые экспорты без имени не участвуют в сопоставлении; их исходные узлы сохраняются.

`sourceInstances` содержит все пары sceneId/sourceNodeId. `states` содержит однозначные ссылки; одинаковые имена внутри одной сцены попадают в `ambiguousScenes`, без случайного выбора экземпляра. Коллизия не запрещает переходы остальных объектов и однозначных состояний.

В реестре нет копии геометрии. Resolver читает source/scene.json: матрицу относительно сцены, dimensions, локальную opacity, visibility, appearance/asset refs, полный путь предков, layerPath, inherited opacity, clipping и действующие sibling masks. Геометрия в контексте AI и runtime — вычисляемая проекция исходников.

Реестр создаётся при импорте, обновляется при reimport и лениво появляется у старых проектов. Название не изменилось — logical ID сохраняется даже при замене Figma node IDs. Переименование создаёт новый объект. Ранее сохранённые motion.json, Undo/Redo и notes не переписываются импортом. Проверка ссылок сохраняется в `motion/source-reference-report.json`; исходный реестр и отчёт архивируются при reimport. Старые операции с отсутствующими targets не переадресуются. Некорректный Motion State сохраняется, но не рендерится/не экспортируется до исправления ссылок агентом. Исторический Undo-снимок также проверяется относительно текущего source.

## Операции и геометрия

Motion State 1.0.0 дополнен необязательным массивом `objectTransitions`; прежние проекты и анимации совместимы.

```json
{
  "type": "animateObjectStateTransition",
  "transitionId": "qr-scene-2-to-3",
  "logicalObjectId": "<ID из реестра>",
  "fromSceneId": "<scene 2>",
  "toSceneId": "<scene 3>",
  "startFrame": 90,
  "durationFrames": 30,
  "easing": "overshoot",
  "proceduralEffects": [
    {"type":"dampedOscillation", "amplitude":0.08, "cycles":2, "damping":3}
  ],
  "layerPolicy": {"type":"switch", "switchProgress":1}
}
```

Операция делает upsert по transitionId. Удаление — `removeObjectStateTransition`. Значения и ссылки проверяются до атомарной записи и добавления записи Undo.

Все времена — глобальные кадры проекта. Переход начинается внутри исходного блока и заканчивается на первом или более позднем кадре целевого блока; конечный кадр должен существовать. Поддерживаются соседние блоки; для длинного пути создаётся цепочка. Каждый участвующий sceneId должен иметь один блок. До начала и после конца действуют обычные исходные сцены; объект не появляется в сценах, где его нет.

Рендерер переводит обе матрицы в общую систему canvas с учётом contain-масштабирования сцены. Нормализованная матрица включает width/height. Affine decomposition сохраняет translation, отдельные scaleX/scaleY, rotation и shear. Вращение идёт по кратчайшей дуге. Origin — исходный локальный (0,0). Вставочная матрица вычисляется как inverse(parentCanvas) × interpolatedNormalized × inverse(dimensions) × inverse(local). Поэтому смена родителя не приводит к сложению несовместимых координат или двойной трансформации.

Spring и затухающая синусоида имеют непрерывное достижение цели; огибающая колебаний равна нулю вместе с производной в конце. Конечная матрица берётся точно из целевого состояния. Отражения между состояниями разного знака и вырожденная геометрия отклоняются. Экстремальный overshoot масштаба ограничен положительным ненулевым значением, чтобы избежать выворачивания изображения.

## Композиция и явные ограничения первой версии

Дерево SVG не расплющивается. Согласно [Figma children](https://developers.figma.com/docs/plugins/api/properties/nodes-children/), порядок массива — снизу вверх. Экспортёр уже сохранял parentId, children, layerOrder и матрицы. Добавлен [itemReverseZIndex](https://developers.figma.com/docs/plugins/api/properties/nodes-itemreversezindex/): Auto Layout может менять порядок наложения. Mask scope определяется исходным порядком siblings, независимо от обратного рисования. SVG fragment IDs изолированы между сценами, чтобы маски и градиенты одной сцены не ссылались на другую.

**Важный компромисс:** во время state transition используется целиком одна композиция пары сцен. До `switchProgress` — исходное дерево, начиная с него — целевое. Это одновременно переключает порядок, содержимое, clipping, masks, blend/group opacity и остальные объекты сцены. По умолчанию switchProgress=1, то есть переключение в конце движения. Геометрия и локальная opacity управляемого объекта непрерывны. Никакой интерполяции layer index.

Если у пары был Crossfade, на время перехода он заменяется этой дискретной композицией; предупреждение видно в результате AI и диагностике. Сохранить одновременно произвольный crossfade двух деревьев, групповую композицию и один экземпляр объекта текущая версия не обещает. Если маски, контент, родительская прозрачность или слой существенно различаются, их переключение может быть заметно — это явно сообщается, а не маскируется под точный морфинг.

Исходный и целевой QR остаются в своих деревьях, но на каждом кадре отображается только одна композиция. Обёртка видимого экземпляра получает промежуточную глобальную геометрию. Невидимая копия не участвует в рисовании. Разные ассеты переключаются внутри этой единственной репрезентации; растрового морфинга нет.

Несколько переходов одновременно допустимы для одной пары сцен при одинаковом тайминге и точке смены дерева. Переход группы конфликтует с переходом её потомка. Независимые анимации управляемого subtree/предков отклоняются, потому что у геометрии должен быть один владелец; их характер переносится в proceduralEffects. Переход самого mask node не поддерживается, маска продолжает работать как контекст визуального объекта.

Остальные ограничения старого renderer (шрифты, некоторые эффекты, SVG fallback) остаются. Переход не доказывает пиксельное равенство Figma.

## AI, preview и MP4

Контекст содержит logicalObjects, source instances, resolved states, слой/родителей/маски, scene order, global timeline, current motion, selected logical ID и историю. Агент выбирает тайминг и характер, но не задаёт конечные координаты из головы. Follow-up меняет тот же transitionId. Валидация операций, максимум три попытки исправления и ограниченный Codex API сохранены. Системные разрешения не отключались.

Iframe и MP4 используют одинаковые `motionHtml` → browser runtime → `applyFrame` → `applyObjectTransitions`. Нет второго видео-движка. Source previews используются только в сравнительном тесте, никогда для движения или реконструкции.

MP4 на 36 кадров декодируется FFmpeg; промежуточный кадр сравнивается с screenshot preview с допуском H.264.

Отдельно выполнены **настоящие запросы Codex SDK** в браузере на неизменённой копии существующего Figma-экспорта `projects/test3/source` (новая сессия Figma не запускалась). Объект называется `куар`; обе сцены ссылаются на один image asset. Создан переход 90→120, overshoot и amplitude 0.08/cycles 2/damping 3. Follow-up изменил его на 99→120 и amplitude 0.12, сохранив transitionId и остальные операции. Autoplay, Undo/Redo, один управляемый экземпляр на каждом кадре, неизменность source и MP4 180 кадров / 30 FPS подтверждены; browser errors = 0.

## Обновление экспортёра

Сборка `figma-motion-exporter/dist` обновлена, manifest ID сохранён. Закрыть старое окно плагина и снова запустить Development → Motion Exporter. Если импортировать заново: Plugins → Development → Import plugin from manifest → `figma-motion-exporter/manifest.json`. Для макетов Auto Layout с обратным наложением нужен новый ZIP. Для обычных существующих экспортов реестр и переходы работают без повторного экспорта.
